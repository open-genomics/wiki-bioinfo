# 内容质量深度治理设计

## 背景

BioInfo Wiki 项目已完成基础架构建设，进入收尾阶段。为提升知识库质量，需对 26 个知识领域进行全面内容治理。

## 目标

对 src/content/docs/ 下所有文档进行四维度检查：
1. **内容完整性**：问题动机、概念解释、实例、前置知识、交叉链接
2. **知识连贯性**：链接有效性、概念引用、前置可达、知识图谱连通
3. **技术准确性**：LaTeX 公式、术语标注、算法描述、代码示例
4. **格式一致性**：frontmatter、空格、标题层级、代码块语言、标点

## 策略：分层渐进式治理

### 分层依据

| 层级 | 领域 | 文件数 | 优先级理由 |
|------|------|--------|------------|
| **基础层** | intro, foundations | 31 | 入口 + 被最多依赖 |
| **方法层** | alignment, models, sequence, core-methods | 45 | 核心算法密集区 |
| **应用层** | 15 个应用领域 | ~80 | 应用场景 |
| **专项层** | databases, formats, data-references, appendix | ~50 | 参考资料 |

### 执行流程

```
阶段 0：准备
├── 读取 style-guide.md 建立检查基线
├── 运行 npm run check 确保构建正常
└── 创建进度追踪文件

阶段 1：基础层治理（并行 2 Agent）
├── Agent 1: intro/ (6 文件)
└── Agent 2: foundations/ (25 文件)

阶段 2：方法层治理（并行 4 Agent）
├── Agent 1: alignment/ (15 文件)
├── Agent 2: models/ (14 文件)
├── Agent 3: sequence/ (13 文件)
└── Agent 4: core-methods/ (3 文件)

阶段 3：应用层治理（分 2 轮）
├── 第一轮: variants, transcriptomics, single-cell, epigenomics
├── 第二轮: population, long-read, spatial, proteomics 等
└── 每轮 4 Agent 并行

阶段 4：专项层治理（并行 3 Agent）
├── databases/, formats/
├── data-references/
└── appendix/

阶段 5：跨领域一致性检查
├── 全局链接检查
├── 术语一致性检查
└── 导航结构检查
```

## 检查清单

### 维度 1：内容完整性

- [ ] 是否有明确的问题动机（"为什么需要这个方法"）
- [ ] 核心概念是否解释清楚
- [ ] 是否有实例或图示辅助理解
- [ ] 前置知识是否说明
- [ ] 是否有交叉链接到相关主题

### 维度 2：知识连贯性

- [ ] 内部链接是否有效
- [ ] 概念引用是否指向正确的文档
- [ ] 前置知识是否可达
- [ ] 知识图谱是否连通

### 维度 3：技术准确性

- [ ] LaTeX 公式是否正确渲染
- [ ] 公式是否有文字解释
- [ ] 术语首次出现是否有英文标注：格式为"中文（English, 缩写）"
- [ ] 算法描述是否准确
- [ ] 代码示例是否可运行

### 维度 4：格式一致性

- [ ] frontmatter 是否正确（title, description 等）
- [ ] 中英文之间是否有空格
- [ ] 标题层级是否合理（H2-H4）
- [ ] 代码块是否指定语言
- [ ] 标点符号是否统一

## 问题严重级别

| 级别 | 定义 | 示例 | 处理策略 |
|------|------|------|----------|
| **P0-Blocker** | 构建失败 | LaTeX 语法错误、frontmatter 缺失 | 立即修复 |
| **P1-Critical** | 核心缺失/严重错误 | 关键概念未解释、公式错误 | 当场修复 |
| **P2-Major** | 影响阅读/完整性 | 缺少交叉链接、前置知识不清 | 批量修复 |
| **P3-Minor** | 风格不统一 | 标点混用、空格不规范 | 记录待办 |

## 进度追踪
